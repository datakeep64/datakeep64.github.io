News Intelligence System

An end-to-end pipeline for processing news content — from multi-outlet RSS collection through classification, named-entity extraction, deduplication, embedding-based search, and cross-source event clustering that groups one story across outlets and flags where their coverage diverges in tone.

Python feedparser (RSS) spaCy NLTK / VADER Scikit-learn TF-IDF Sentence-Transformers Agglomerative Clustering

How It Works — in Plain English

Every day, hundreds of stories come in from different news outlets, and many of them cover the same events. This system reads them automatically and answers four questions: What is each story about? Who is it about? Which stories are really the same event? And can I find a story by what it means, not just by the exact words it uses?

Each article goes through the same steps once. Every step adds something to the article, and nothing is thrown away.

2 · Turning words into numbers

Computers can't read words directly, so every piece of text is first turned into a list of numbers. The system does this in two ways.

TF-IDF
Word counts, weighted by how telling a word is
Common words that appear everywhere get almost no weight. Rare, specific words get a lot. Example weights:
“said”
“bank”
“inflation”
Used for: topics, summaries, duplicates, keyword search, events.
Embeddings
A model's sense of what the text means
A small pretrained model (all-MiniLM-L6-v2) turns a whole sentence into 384 numbers. Sentences with similar meanings end up close together, even when they share no words.
Used for: meaning-based search.

Why not plain Bag of Words? Bag of Words only counts words. TF-IDF uses the same counts but also down-weights words that appear everywhere, so “said” doesn't drown out “inflation”. It also counts two-word phrases like “interest rates” as one unit.

3 · How search ranks results

A keyword search for “car makers” misses an article about “automotive manufacturers” because they share no words. A meaning search finds it. The system combines both scores.

Query
“rising borrowing costs”
↓
Meaning score · 70%
How close the embeddings are. This finds stories that use different words for the same thing.
Keyword score · 30%
TF-IDF match. This is precise on exact names and phrases.
↓
Filter
Keep only the topics you asked for
e.g. “Business only”. The topic label comes from the classification step above.
↓
Results
Each result shows both scores, plus the article's topic, names and summary. If the embedding model can't load (e.g. offline), search falls back to keywords only instead of failing.

4 · What “one unified pipeline” means

Before, “understanding” news (topics, names, summaries) and “finding” news (search) were separate tools that read the same feed. Now they are one flow, and each side uses the other's output:

Understanding → Finding
The search index is built from articles that already have topics, names and summaries, so you can filter search results by topic.
Finding → Understanding
In the Analyse tab, you paste any text. The system labels it, then searches the feed for related coverage.

Pipeline Architecture

The same flow in technical terms. Each stage feeds the next, and any stage can be swapped or extended independently.

01

Data Collection

RSS collection with feedparser across multiple outlets (BBC, The Guardian, Sky News, NPR). Structured extraction of headline, summary, source, link, and publish date; failed feeds are skipped gracefully.

02

Text Preprocessing

NLTK cleaning pipeline: HTML/URL stripping, tokenisation, stopword and punctuation removal, and WordNet lemmatisation. Near-duplicate headlines (TF-IDF cosine ≥ 0.82) are then removed. spaCy is used separately for named-entity extraction.

03

Topic Classification

Unsupervised seed-similarity labelling: each article is vectorised with unigram + bigram TF-IDF and assigned the closest of seven hand-written topic descriptions by cosine similarity, or “General” if nothing overlaps. No training data yet, so accuracy has not been measured (see the evaluation plan above).

04

Summarisation

Extractive summarisation: sentences are scored by summed TF-IDF weight times a position decay (the inverted-pyramid structure of news), and the top sentences are kept in their original order.

05

Embedding-Based Hybrid Search

Sentence-transformer embeddings (all-MiniLM-L6-v2) for semantic matching, blended 0.7 / 0.3 with unigram + bigram TF-IDF for exact-phrase precision. The index is built over the NLP-enriched records, so results can be filtered by classified topic. If the model is unavailable, search falls back to keyword mode.

06

Cross-Source Event Clustering

Agglomerative clustering on TF-IDF cosine distance groups articles by underlying event — the event count is discovered from the data, not fixed in advance. Each event surfaces the outlets covering it, the terms they share, and a VADER-based tone-divergence flag when outlets cover the same story with notably different sentiment. (Named tone divergence, not "contradiction" — sentiment spread isn't claim-level entailment.)
